Только исходники `/opt/sochi-portal-staging`. **Живой Docker-образ пока старый, пока не будет rebuild.** py не копировали.

## Кабинет — как устроено
- `/dashboard` = записи (коворкинг/залы/афиша), не «стол» в смысле профиля.
- `/dashboard/me` = публичная страница.
- Хабы: страница / общение / дела / прогресс.
- Админ после логина идёт в `/admin`, из панели есть ссылка «Кабинет».

## Ошибки логики
1. **SCANNER/TECH:** `proxy.ts` пускает в личные `/dashboard/me|settings|messages|friends`, а `CabinetShell` выкидывал всех на `/scanner` и `/ops`. Исправлено в shell.
2. Пункт «Рабочий стол» вёл на записи — название врало. Теперь «Мои записи», хаб открывает `/dashboard`.
3. Админ-пункт «Афиша» на деле **брони/события на модерации**, не публичная афиша. Переименовано в «Брони и события».
4. **Заявки регистрации** (`/admin/pending-users`) были только для ADMIN, хотя это модерация входа. Страница, ACL и API открыты модератору с правом `moderation`. Журнал админов, пользователи, настройки сайта — по-прежнему только ADMIN.

## Удобство (без смены ролей)
- Меню кабинета длинное (витрина, рефералы, награды) — модули режутся флагами.
- Модератор без `permissions` в БД по-прежнему упрётся в `?denied=1` на разделах (нужен заполненный список прав).
- Контент-модерация чатов: `/admin/moderation` (флаги). Регистрации: `/admin/pending-users`. Это разные очереди.
